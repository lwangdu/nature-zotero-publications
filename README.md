# Nature Zotero Publications

A WordPress block plugin that displays live Zotero library data as a year-grouped bibliography with authors, linked titles, publication details, item-type badges, dates, DOI links, citation keys, source URLs, tags, search, filters, and pagination.

## Architecture

- **Dynamic block**: the block has no static saved markup. `includes/class-block.php` registers it with a `render_callback`, so the frontend HTML is always generated fresh from PHP on each page load (subject to caching, see below).
- **Caching**: `includes/class-zotero-api.php` wraps all Zotero API calls. Responses are cached in WordPress transients (default 60 min, configurable in Settings → Nature Zotero Publications). A 7-day "stale" backup transient is also kept so the block can still render something if Zotero's API is temporarily down.
- **REST endpoint**: `includes/class-rest-controller.php` exposes `GET /wp-json/zotero-display/v1/items`. This single endpoint is used by:
  1. The block editor (`src/edit.js`) for the live preview.
  2. The frontend script (`src/frontend.js`) for search/filter/pagination, so those interactions don't trigger full page reloads or extra Zotero API calls (it reads from the same transient cache).
- **Initial frontend render**: `includes/class-block.php::render()` renders page 1 server-side (good for SEO/no-JS), then `frontend.js` progressively enhances it.

## Setup

1. `npm install`
2. `npm run build` (or `npm run start` while developing)
3. Activate the plugin in WordPress.
4. Go to **Settings → Nature Zotero Publications** and enter:
   - Zotero API key (only required for private libraries — get one at zotero.org/settings/keys)
   - Library type (User or Group)
   - Library/Group ID
   - Cache duration in minutes
5. Add the "Nature Zotero Publications" block to any post or page. Per-block settings (in the block inspector) can override the library type/ID/collection for that specific block instance.

The API key is used only in server-side Zotero requests and is never included in block markup or REST responses. Citation keys are read from Zotero's native `citationKey` field, with a fallback for legacy Better BibTeX `Citation Key:` values in the Extra field.

## Notes on Zotero API quirks handled here

- Child attachments and annotations are removed while normalizing the API response. Top-level standalone attachments remain visible so the entry count matches Zotero's "items in this view" count. Untitled top-level records use an "Untitled" display label.
- `abstractNote` is requested via `include=data`; abstracts appear in expandable controls when available.
- Pagination beyond Zotero's 100-item-per-request cap is handled by looping requests in `Zotero_API::fetch_from_api()`. The display fetches up to 1,000 bibliographic items and paginates them locally.
- Year, item type, and author filters are populated from the cached library data. Search covers titles, authors, dates, DOI, citation keys, abstracts, publications, and tags.
- Cache keys are hashed from the full query (library, collection, sort, type) so different block configurations on the same site don't collide or overwrite each other's cache.
